# seed/ — the promoted library (§7.3)

The mechanism by which the method gets stronger per use. At run end, the
owner marks which of the run's new rule rows, checklist lines and
extractors are general — domain-level or universal. Promoted items land
here and the next `vid init` starts with them pre-loaded for ratification:
the owner's expertise as an encoded, compounding asset instead of a
per-run performance.

**The shipped plugin's library starts empty** — the plugin ships no
stack-specific and no domain-specific content anywhere; everything here is
put here by promotion from real runs. The only shipped file with substance
is `extractors/README.md`: the stack-agnostic extractor contract and class
catalog, with the v0.6 worked example as documentation.

- `rules.md` — proposed rows for the genus step (§7.1), by layer
  (universal / stack / domain), each classified to an existing evidence
  tier. Proposals only: the owner vetoes or confirms at recognition speed;
  a vetoed proposal leaves no residue.
- `checklist.md` — grading-checklist lines for `GRADING-CHECKLIST.md`.
- `extractors/` — the extractor contract and class catalog
  (stack-agnostic), plus promoted extractors under per-stack directories.

The deletion rule applies symmetrically: a seeded item that fires nothing
across two runs is dropped (the complexity law, CLAUDE.md §2). Nothing in
this directory is installed verbatim — everything passes through owner
ratification at init.
