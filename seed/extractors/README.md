# Census extractors — the stack-agnostic contract and class catalog

The census engine (`checks/census.sh`) is stack-agnostic and never changes
per project. Everything stack-specific lives in extractors: small scripts
(~10–30 lines) **generated by the model at init from the actual scaffold**,
ratified by the owner, then locked in the project's `checks/extractors/`
with court status and proven by self-test (§4.2) before the run starts.
**The plugin ships no extractor code — no framework, no language, no
harness.** This file is the contract those generated extractors must meet
and the catalog of what each class means, for any stack.

## The contract (what the engine expects)

An extractor is `checks/extractors/<class>.<name>.sh` where `<class>` is
`dead-path` · `invariant` · `divergence` · `reachability` · `vacuity` ·
`rendered` · `strength`.
Run with no arguments from the repo root, it prints:

    ok <subject>                 a population member whose join closes
    orphan <subject> <detail>    a population member missing its other half
    population <n>               optional: declare the denominator without
                                 listing every ok member

- `<subject>` is one token (a key, route, file:line, name) — exactly the
  string an exception or suppression row must name.
- **Silence is failure.** An extractor whose substrate is absent DECLARES
  it: a first line `inactive <reason>`. No output at all, and a population
  of zero, are failures — a census must not silently survive the renaming
  of what it watches. Nonzero exit = failure, never a pass.
- For `divergence`, the orphan detail carries the two values:
  `orphan <knob> test=<v> prod=<v>`.
- Extractors enumerate and join; they never judge. An extractor that needs
  more than ~30 lines is evidence the class is wrong for this stack —
  redesign or drop, never grow.

One extractor sits outside the five classes: **`routes.sh`** — the route
table the inventory court reads (`ok <route>` lines, one per routable
surface, in the same literal form INVENTORY.md subjects use). The plugin
ships no framework parser; this extractor is where the scaffold's routing
convention is encoded, generated and ratified like the rest.

A third shape outside the five (v0.9.2 3.6, R9; the harness contract's
half of §9 Q1): **`results.sh`** — the results reader. The ledger wrapper
(`checks/test.sh`) makes the runner write its per-case results report and
names it by the tree it ran; the plugin's courts never parse a runner's
format. This extractor, generated at init beside `routes.sh`, is where the
stack's report shape is encoded: `sh checks/extractors/results.sh <report>`
prints one line per COLLECTED case,

    case <path>::<name> <passed|failed|skipped|error> <seconds>

where `<path>` is the test file as the inventory cites it
(`tests/invariants/…`), `<name>` the case's own id with its parameters and
engine (one token — the reader replaces whitespace), the status one of the
four words, and `<seconds>` the case's own duration; `inactive <reason>`
when the report is absent or unreadable; nothing else. A report holding no
case prints no `case` line — zero collected is what the courts read.
checks/coverage.sh (`--strict` under the 0.9.2 inventory grammar) and
checks/metrics.sh (the rows headline, the slice claim, per-class seconds)
read only these lines. Same size bound, same selftest case as the rest: a
report with one case of each status must come back as four lines.

A fourth shape outside the five (v0.9.3 3.9, §9.5): **`memory.sh`** — the
host's free memory, for the observer's report. How a host exposes free
memory is the host's business, so init generates this reader for the host
the project runs on, and the plugin names no tool: `sh
checks/extractors/memory.sh` prints one line, `free-mb <n>`, or `inactive
<reason>` when the host exposes nothing it can read; nothing else.
checks/observe.sh compares the number with `.vid/budget`'s
`memory-headroom-mb` and REPORTS it — never a refusal (the measured
incident was stacks at once, which the host lease enforces). Absent, the
observer says memory is not exposed. Same size bound, same selftest case as
the rest: the reader prints exactly one line of one of the two shapes.

A second shape outside the five: **`state-machine.<field>.sh`** — the
denominator of a state-machine rule row (§6.1), cited by that row as its
census command. It is never run as a class census; its contract is the
rule's: one line per site that mutates or guard-reads the field —
`<site> <from>><to>` for a mutation, `<site> <state>` for a guard read —
and `inactive <reason>` when the substrate is absent. The census engine
judges its lines against the row's declared table, naming any undeclared
transition or state. Same size bound, same selftest case as the rest.

## The classes, stack-agnostically

| Class | Left set | Right set |
|---|---|---|
| `dead-path` | producers (writes, definitions, registrations) | consumers (reads, calls, links) |
| `invariant` | sites a rule applies to | sites guarded |
| `divergence` | knobs under test config | same knobs under prod config |
| `reachability` | stated surfaces | inbound navigation paths |
| `vacuity` (report-only) | assertions in row-bound tests | a reachable failing mode |
| `rendered` (report-only) | canvas-pinned load-bearing properties per design marker | computed values on the running page |
| `strength` (report-only, v0.8.1d) | row-bound tests of Tier-0 rows | an assertion above Existence on the ladder Existence → Type → Status → Value → Behavioral |

One `dead-path` instance is **mandatory at every init** (v0.8.1d, the
vid-test-inventory skill's shape 9): `dead-path.collected-fields.sh` —
population = every field the product collects from a user and stores;
right set = a read site other than validation and display. The measured
class: two fields validated, required, displayed, and read by nothing.

A second `dead-path` instance is **mandatory at every init** (v0.9.3 3.4,
R5): `dead-path.topology.sh` — the topology census, generated from the
scaffold as the route table is. **Population:** every task-to-queue
routing and every schedule the product declares. **Join:** a declared
process (the harness contract's `processes:` in docker-compose.test.yml,
its command and configuration) consuming that queue, or a registered task
for that schedule's target. **Lines:** `ok queue:<name>` · `orphan
queue:<name> no declared process consumes it` · `ok schedule:<name>` ·
`orphan schedule:<name> names unregistered task <task>`. **Arming:** it
prints `inactive no routing or schedule declared` until the first routing
OR the first declared schedule exists — a schedule-only product must not
stay unarmed. It is a class extractor, never a rule row: the census skips
an `inactive` class extractor, whereas a rule row's command handed
`inactive` meets the zero-population rule. An orphan whose queue or
schedule a ratified `difference` row (its knob) or a deploy-owed ROW (its
subject) names as a platform-only consumer is printed as a ratified
divergence, never an orphan (checks/census.sh); the platform half of that
obligation is paid at deploy gate 2. The join is against the harness's
declared processes — narrower than the platform's launch configuration,
which only a deploy observes. The measured class: queues no worker
subscribed to, and a scheduler nobody registered, found first by the end
grade.

What each class enumerates is per-stack, derived at init from the scaffold
in front of the session: config/env keys defined↔read; persisted fields
written↔read (or tagged write-only); route identifiers↔references to them;
rendered links↔resolving routes; event/handler registrations↔emitters;
scheduled and operational jobs↔their invocation records; flags
defined↔parsed. These are shapes, not shipped code.

The `vacuity` shapes are law (§3.1); their concrete realization is
generated at init for the ledger's own harness: `or True` / or-constant,
literal-vs-literal comparisons, bare catch-all exception assertions,
status tuples spanning success and error, skip-on-the-condition-under-test
— **rebuilt from the measured classes** (v0.8.1d; the five above fired
nothing across a whole field run while the ledger carried the shapes they
could not see): a status assertion spanning success codes with no error
code; a presence-only browser assertion keyed to a static wrapper that
renders even in the empty state; a substring filter matching nothing; a
zero-population loop; a placeholderless format string inside an
assertion; and the circular fixture — a fixture file whose one-line
`Provenance:` header names the product itself, or is absent. Report-only
until the first run measures its false-positive rate, then promoted to
fail-closed or deleted on the number.

The `strength` class (v0.8.1d) classifies each row-bound test's
assertions on the ladder Existence → Type → Status → Value → Behavioral
(joined to rows through INVENTORY.md's test paths) and emits an orphan
for a Tier-0 row whose strongest assertion is Existence; subject is
`<file>:<line>`, detail names the row and the strongest level. Report-only
under the same promote-or-delete gate; the census prints its orphans as
`STR` lines. **The grain is the function (v0.9.2 3.9a, R13):** "each
row-bound test" is the test FUNCTION whose name or docstring names the
row id — never the file; the scan is scoped to that function, so a
value-level assertion elsewhere in the cited file does not lift an
Existence-only row. A row whose cited file holds no such function emits
`orphan <file> unbound-row <row id>` — the row is bound to nothing the
class can read. The generated extractor and its selftest case follow the
grain: a fixture file holding one value-level test beside a Tier-0 row
bound to an Existence-only function → exactly one orphan (the row's); the
same file read at file grain → zero, the mutation the case must fail on;
a row naming no function → `unbound-row`.

**The repair and the measure (v0.9.8, R11).** Two runs measured both
classes at 0 true reports in 10 sampled each. Three causes, repaired in
what a generated extractor must do:
- **Vacuity, the placeholderless format string:** a message is read to its
  own closing quote. A quote of the other kind inside it, or an escaped
  one, is text: reading stops at the first apostrophe was the measured
  bug (282 of one run's 341 vacuity reports).
- **Strength, the parameterised test:** one test function run over a table
  of rows binds every row its table names — a row id in the table's data
  names that row, as a name or docstring does. Reporting such rows
  `unbound-row` was the measured bug (3 of 10 sampled).
- **Strength, the ladder:** an assertion comparing what the action produced
  — a value read from its result — with an expected value is Value or
  Behavioral. Existence is only present, absent, empty or a count above
  zero, with no expected value. Reporting behaviour assertions as
  existence was the measured bug (7 of 10 sampled).

**The measure:** each generated vacuity and strength extractor ships with
a labelled fixture, `checks/selftest/fixtures/detectors/`: a small tree in
the project's own stack — row-bound tests and the INVENTORY.md rows that
bind them — holding known weak tests (each shape the class claims, the
three repaired ones among them) and known good ones (their near misses: a
message with an apostrophe, a parameterised table, a value comparison),
and `labels`, one line each: `weak <class> <subject> <rule>` or `good
<class> <subject>`, where an orphan's rule is the first word of its
detail. `sh checks/census.sh --measure checks/selftest/fixtures/detectors`
prints, per class and rule, tp, fp, fn, precision and recall — counts over
counts. Both classes stay advisory until a later release sets a bar.

**Selftest cases plant mutations beyond the canonical shape** (v0.8.1d):
each generated extractor's case in `checks/selftest/cases/` seeds, besides
the canonical known-bad fixture, at least one unguarded site written in a
non-canonical form (a second vocabulary for the same guard — a guard
replaced by a constant, a state token spelled differently) and, for a
rule row's compound census command, one arm-broken command (a syntax
error in one arm) that the engine must convict rather than let shrink the
population. The measured case: three Tier-0 mutations left "72 sites, 72
guarded" untouched.

## The rendered class (v0.8 §9 — the deterministic half, report-only)

A shared element (the shell, a card, the top bar, an overlay, a badge, a
heading) is compared to the components canvas C00's section, never to
another screen (v0.9.1 3.7a).

Population: for each design marker, the LOAD-BEARING properties its
canvas section pins — owner-ruled scope, deliberately small: the
paint-integrity set (display, visibility, opacity, position offsets, a
non-zero rendered box) plus the identity colors (color,
background-color). Obligation: on the RUNNING page, the element's
COMPUTED value matches the canvas value. Catches specificity collisions,
overridden and never-applying rules, elements painting empty /
zero-height / transparent, off-screen positioning, collapsed layout —
all of which pass a DOM-presence assertion today. Realized at init
against the project's own browser harness (the same Docker-only harness
the ledger's browser class uses); the plugin ships no browser code. Since
v0.9.2 (3.4) the extractor CALLS the measure module below and is no second
comparison: it enumerates the routed markers, hands each state to the
module and prints the module's `differs` lines as its orphans.
Contract specifics:

- subject is `<marker>:<property>` (`P02/populated:background-color`);
  the orphan detail carries both sides: `cited=<v> computed=<v> <why>`.
- numeric lengths compare with a ≤1px tolerance (sub-pixel rounding);
  font-metric-dependent values are out of scope by the owner's ruling.
- the extractor declares `inactive <reason>` whenever the rendered
  surface is not up: it runs at slice close with the ledger, not per
  commit — browser tests are the slowest tier and the class is
  report-only regardless.
- REPORT-ONLY: orphans print as `REND` lines and never fail a commit,
  until a real run measures the false-positive rate — then promoted
  fail-closed or deleted on the number (the vacuity retrofit pattern).
- never image equality: named properties against ratified values only —
  pixel-diff baselines stay refused.

## The measure module (v0.9.2 3.4, R7, R20 — one driver, three readers)

The surface instrument (`tests/invariants/<surfaces file>`, a file per
screen for new projects (v0.9.8.1 R18), the surface
test-author pass's product — vid-test-inventory `passes/test-author.md`),
the rendered extractor and the fidelity graders read the running page
through ONE module. It is installed at init with the harness, under
`tests/invariants/` beside the harness client, in the stack's own
language, named `measure` (`tests/invariants/measure.<ext>`); the rendered
extractor invokes it and is no second comparison. The plugin ships no
browser code: this is the contract the generated module meets, and the
shape the selftest fixture (`checks/selftest/fixtures/surface-instrument/`)
realises in shell over a toy page reader so the instrument's checker can
run without a browser.

**One operation per state.** The caller hands it an engine (one the
harness contract declares), an actor (the harness's actor door signs the
actor in before the load; `anonymous` needs no door), a route, the marker
and state (`P02/populated`), and the state's **literal set** — what the
canvas section declares, read at PRODUCTION time by the pass and carried
by the instrument itself: for the section root (identifier `root`) and
for every element carrying an identifier (`data-element`, vid-design §1
rule 5) every property the canvas declares on it; the content the canvas
draws for the state (its literal text outside `{{ placeholders }}`); the
controls the canvas draws for the state. The module answers with lines
and nothing else:

    navigations=<n>
    ok <marker>/<state>/<identifier>:<property>
    differs <marker>/<state>/<identifier>:<property> cited=<v> painted=<v>
    missing element <marker>/<state>/<identifier>
    stray <marker>/<state> <identifier or control>
    missing marker <marker>/<state>
    missing content <marker>/<state> <text>
    console error <marker>/<state> <message>
    status <marker>/<state> <code>

Four rules, the ones the instrument's checker counts:

- **One navigation per state.** The route is loaded once per case;
  `navigations=` says how many loads the call made, and the checker
  expects states × engines over a run. The pins hook reads the SAME loaded
  page — a hook that navigates is a defect.
- **One evaluate.** Every property of every identified element — layout,
  spacing, type, colour, radius — is read in one script evaluation against
  the loaded page: the section root mapped by its marker, each descendant
  by its identifier inside that section. Property count is not the cost;
  navigation was.
- **Colours as colours, lengths as computed lengths.** The cited literal is
  resolved in the SAME browser through a probe element — a token, a hex, a
  functional notation compare as the colour they paint, never as strings;
  a length declared in one unit and painted in another compares as the
  computed length, with the rendered class's ≤1px tolerance. A literal the
  browser cannot resolve is not a finding.
- **The denominator rule.** A stray control is any control on the page
  OUTSIDE THE SHELL — the shell being what stands under the shell rows'
  markers (header, footer, primary navigation) — that the canvas state
  does not draw; never the box the implementation labelled. An identifier
  the page carries inside the section that the canvas state lacks is
  reported on the same `stray` line.

What the readers make of the lines: the instrument turns `missing
marker`, a `status` other than the page's own, `missing element`,
`missing content`, `stray`, `console error` and every `differs` into a
FAILING case naming the row — never a deferral (3.4); the rendered
extractor (report-only, slice close) prints each `differs` as its
`orphan`, the subject gaining the identifier segment
(`P02/populated/root:background-color`,
`P02/populated/featured-grid:grid-template-columns`) — one comparison,
two readers; the fidelity grader (vid-grade) cites the same lines where
it can and reads the canvas where an element carries no identifier — the
honest limit the join court reports.

## Worked example (documentation only — never installed)

The v0.6 field run's tree (a Django job board) is the evidence the classes
are mechanically enumerable on a real codebase: 133 settings keys, 64 URL
names, 119 dynamic hrefs. The dead-path config-keys extractor for that
stack, in full — the shape init should produce for whatever stack it
actually scaffolds:

```sh
#!/bin/sh
# Purpose: census extractor — dead-path: config keys defined and never read.
set -eu
IFS='
'
SETTINGS=$(find . -name 'settings*.py' | grep -vE '/(tests|checks|venv)/' || true)
[ -n "$SETTINGS" ] || { echo "inactive no settings module in this tree"; exit 0; }
FRAMEWORK='DEBUG ALLOWED_HOSTS INSTALLED_APPS MIDDLEWARE ...'   # consumed by the framework itself
for k in $(cat $SETTINGS | grep -oE '^[A-Z][A-Z0-9_]+ ?=' | sed 's/ *=//' | sort -u); do
  case " $FRAMEWORK " in *" $k "*) echo "ok $k"; continue ;; esac
  if grep -rqE "settings\.$k\b" --include='*.py' . 2>/dev/null; then
    echo "ok $k"
  else
    echo "orphan $k defined in settings, read nowhere in app source"
  fi
done
```

The equivalent for a Node scaffold enumerates `process.env.X` reads against
`.env.example` definitions; for a CLI, flags defined against flags parsed.
Same contract, same size, different substrate.

## Promotion

Extractors an owner marks general at run end are promoted here (§7.3),
under a directory named for their stack, as templates for the next init.
The deletion rule applies symmetrically: a seeded item that fires nothing
across two runs is dropped.
